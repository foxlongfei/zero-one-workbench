# ZERO-CORE｜平台核心规则 V0.1

状态：ACTIVE_SUB
层级：两个业务项目之上的公共基础设施 SUB；不得取代“零一空间研究”Z05或“动起来”正式主线。

## 核心定义
零一空间拥有自己的数据、记忆、知识、任务和版本；C/Q/D及未来模型只是可替换的 Provider/Agent Adapter。浏览器、App、小程序、本地客户端只是终端，不拥有主数据。

## 固定架构
终端 → ZERO-CORE API → 身份/权限 → 对话/项目/知识/任务主库 → AI Adapter → 事件/看板 → 导出与备份。

## 数据主权
1. 主库/核心规则由零一空间自己的 schema 表达，不使用任一模型厂商的会话格式作为永久主结构。
2. 每条对话至少保留：actor、project、thread、timestamp、raw_content、provider/model、关联任务、关联知识/成果、版本/审计状态。
3. 对话不是知识：只有经过明确归档/提炼的内容才能进入知识层；原始对话保留来源链。
4. 云端是运行主库；必须支持完整导出、本地副本和可迁移重建。

## 身份与权限
V0.1 角色预留：OWNER、COLLABORATOR、EVALUATOR。以后可扩展，不把当前四个参与者写死成权限模型。
登录是平台入口；对话小窗/侧栏是登录后的组件。项目、知识、费用和审计均绑定身份与工作空间。

## AI 接入
- Provider Adapter：C / Q / D / FUTURE_PROVIDER。
- 路由可按成本、能力、独立复核和任务角色选择单模型或多模型。
- Q/D/C产出只有形成可查交付并绑定项目节点，才算项目进度。
- API Key/secret只存在服务端secret manager或环境变量；不得进入GitHub、浏览器JS、App包或导出数据。
- 任何模型不可直接获得超出当前用户/任务权限的数据。

## 对话→项目事件
conversation → decision → task → artifact → knowledge → version。
自动建议可以产生草稿事件，但改变MAIN/SUB/TEMP、完成状态、核心规则或正式知识时必须保留可审计事件和来源。

## WYSIWYG
每个真实动作必须同步：做了什么 → 可点击原物 → 推进哪个节点 → 下一步。
ZERO-CORE后台建设本身不能冒充Z05或动起来产品进度。

## V0.1完成门
可见登录入口 + 工作空间选择 + C/Q/D选择 + 对话界面 + 持久化主库 + 至少一个真实Provider服务端调用 + 会话可导出备份 + 看板事件可追踪。
