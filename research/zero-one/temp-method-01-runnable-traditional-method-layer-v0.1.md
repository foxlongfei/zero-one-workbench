# TEMP-METHOD-01｜古法可运行方法层 V0.1

状态：ACTIVE
类型：TEMP
来源：用户指出现有知识/关系为碎片，缺少“给真实输入即可运行”的方法论。
返回点：Z04 / K02-03-HXL-01；不替代既有主线、基础知识库或证据模型。

## 问题定义
当前已有 SOURCE / OBJECT / EDGE / CLAIM / EVIDENCE，但“知道有什么”不等于“会运行”。
新增 METHOD 层，把古代术数/方技中可描述的程序转成可复现流程；不预设其有效性。

## METHOD_CARD V0.1
每个方法必须具有：
- METHOD_ID / 名称 / 流派或文本传统 / 时期
- INPUT_SCHEMA：真实输入需要什么
- NORMALIZATION：历法、时间、方位、尺度、名称等如何标准化
- PROCEDURE：严格有序步骤
- RULE_TABLE：每一步调用哪些规则/知识对象
- DECISION_NODES：出现分支时如何选择
- OUTPUT_SCHEMA：方法本身会输出什么
- SOURCE_BINDING：每条规则的原典/注疏/后世来源
- VARIANT_RULES：不同流派/版本冲突，不强行合并
- WORKED_EXAMPLE：完整可复算案例
- REPRODUCIBILITY：另一执行者能否从同输入得到同输出
- VALIDITY_BOUNDARY：材料存在/历史使用/内部一致/结果可复核/机制可解释分开记录
- OPEN / CONFLICT / HOLD

## 第一阶段只做两个“运行探针”
A. 生辰八字输入探针
目标不是“算准”，而是检验系统能否从出生年月日时开始，按一个明确历史方法完成：输入校验→历法/干支转换→排盘→调用规则→生成结构化结果，并逐步显示依据。
若缺地点、历法、时制或流派，必须明确指出缺项，不自行补造。

B. 房屋结构/风水输入探针
目标不是“看风水结论”，而是检验系统能否从平面结构、坐向、门窗/房间位置等输入开始，选择一套明确方法，完成标准化→方位/宫位排布→规则调用→结构化结果，并显示每一步来源。
不同传统不得混算成一个“风水”。

## 展示纪律
后台知识可多，前台默认只显示：
1. 你给了什么
2. 采用哪一种方法
3. 现在算到哪一步
4. 得到了什么
5. 为什么（点击展开来源/分歧）
关系网、证据图、全部知识节点默认折叠，不直接铺满页面。

## V0.1 完成门
至少一个运行探针形成端到端可复算样板：
INPUT → METHOD → STEP TRACE → OUTPUT → SOURCE TRACE
并通过同输入重复运行一致性检查。
仅有资料、关系图、规则列表，不算完成。
